# filtman — Telegram Filter Manager

Инструмент для декларативного управления папками (фильтрами) чатов в Telegram через CLI.

## Концепция

Состояние папок описывается в файле `filters.toml`. Пользователь редактирует файл вручную, затем применяет изменения командой `push`. Для получения текущего состояния из Telegram используется команда `pull`.

Модель похожа на git: `pull` скачивает состояние, `push` применяет локальные изменения. `filters.toml` — единственный источник правды после pull.

## Файлы

### `filters.toml`

Основной файл конфигурации. Редактируется пользователем вручную.

```toml
[filters.1]
title = "Работа"
channels = [123456789, 987654321]

[filters.2]
title = "Мемы"
channels = [111111111, 222222222]

[filters.3]
title = "Политика"
broadcasts = true
channels = []
```

Поля каждого фильтра:

- `title` — название папки (обязательное)
- `channels` — список chat_id чатов (peers) в папке
- `broadcasts` — включить все каналы (флаг, опциональный, по умолчанию false)
- `contacts` — включить все контакты (флаг, опциональный)
- `groups` — включить все группы и супергруппы (флаг, опциональный)
- `bots` — включить всех ботов (флаг, опциональный)
- `exclude_muted` — исключить беззвучные чаты (флаг, опциональный)
- `exclude_read` — исключить прочитанные чаты (флаг, опциональный)
- `exclude_archived` — исключить архивные чаты (флаг, опциональный)

Числовой id секции (`[filters.1]`) — это прямой id фильтра из Telegram API. Не придумывается пользователем, берётся из Telegram при `pull`.

### `filters.lock.toml`

Снимок состояния Telegram на момент последнего `pull`. Генерируется автоматически, пользователь его не редактирует. Используется командой `push` для обнаружения конфликтов.

## CLI команды

### `pull`

Скачивает текущие фильтры из Telegram и записывает в `filters.toml` и `filters.lock.toml`.

**Логика:**

1. Получить фильтры из Telegram.
2. Если `filters.toml` уже существует — сравнить его с тем, что пришло из Telegram.
3. Если в `filters.toml` есть фильтры, которых нет в Telegram (или наоборот) — показать diff и запросить подтверждение перед перезаписью.
4. Записать новый `filters.toml` и `filters.lock.toml`.

### `push`

Применяет `filters.toml` к Telegram.

**Логика:**

1. Прочитать `filters.toml` и `filters.lock.toml`.
2. Получить текущие фильтры из Telegram.
3. Сравнить текущее состояние Telegram с `filters.lock.toml`. Если они расходятся — значит Telegram был изменён извне (другое устройство, официальный клиент) после последнего `pull`. Показать что именно изменилось и запросить подтверждение.
4. Показать пользователю что именно будет сделано:
   - какие фильтры будут созданы
   - какие обновлены
   - какие удалены (фильтры из Telegram, которых нет в `filters.toml`)
5. Запросить подтверждение.
6. Применить изменения через Telegram API.
7. Обновить `filters.lock.toml`.

**Важно:** `push` полностью синхронизирует Telegram под `filters.toml`. Фильтры в Telegram, которых нет в `filters.toml`, будут удалены. Папка "All Chats" (виртуальная, id=0) не трогается никогда.

### `diff`

Показывает разницу между `filters.toml` и `filters.lock.toml` — то есть что именно будет применено при следующем `push`. Работает без подключения к Telegram.

```
$ filtman diff
  + [5] Новая папка
  ~ [1] Работа
      channels: [123, 456] → [123, 456, 789]
  - [3] Политика
```

Цвет: зелёный для новых фильтров, жёлтый для изменённых, красный для удалённых.

### `exclude <target_id> --from <source_id>`

Добавляет все peers фильтра `source_id` в список `exclude` фильтра `target_id`. Одновременно удаляет эти peers из `channels` и `pinned` фильтра `target_id`, если они там присутствуют. Работает без подключения к Telegram — изменяет только `filters.toml`.

```
$ filtman exclude 1 --from 2
  ~ [1] Работа
      exclude: [] → [111111111, 222222222]
      channels: [111111111, 222222222, 333333333] → [333333333]
Применить? [y/N] y
```

Используется когда нужно, чтобы папка A не показывала чаты, уже входящие в папку B.

### `find-channel <query>`

Ищет канал среди диалогов пользователя по названию (частичное совпадение). Возвращает id и название найденных совпадений.

Используется чтобы узнать chat_id канала перед добавлением его в `filters.toml`.

```
$ filtman find-channel "breaking"
123456789  @breakingmash  "Breaking Mash"
987654321  (private)      "Breaking News RU"
```

## Контекст: как устроены фильтры в Telegram

Папки в Telegram называются `DialogFilter` на уровне MTProto API. Каждый фильтр содержит:

- `include_peers` — список конкретных чатов, включённых в папку
- `pinned_peers` — список закреплённых чатов внутри папки
- `exclude_peers` — список чатов, явно исключённых из папки
- флаги (`broadcasts`, `groups`, `contacts` и т.д.) — включить целую категорию чатов без перечисления

Чаты в Telegram идентифицируются через **peer** — объект, содержащий числовой id и `access_hash`. `access_hash` — токен безопасности, который Telegram выдаёт при первом контакте с чатом. Hydrogram хранит их в файле сессии (`takoo.session`). В `filters.toml` хранятся chat_id (числа), при `push` они резолвятся в peer-объекты через локальную базу сессии.

Папки в Telegram **не эксклюзивны**: один чат может быть в нескольких папках одновременно. "All Chats" — виртуальная папка (id=0), которая всегда содержит все диалоги и не управляется через API.

## Типичный рабочий процесс

**Первоначальная настройка:**
```
pull                          # получить текущее состояние из Telegram
# отредактировать filters.toml
push                          # применить изменения
```

**Добавить канал в папку:**
```
find-channel "Название"       # узнать chat_id
# добавить id в нужный фильтр в filters.toml
diff                          # проверить что получилось
push                          # применить изменения
```

**Реорганизовать папки:**
```
pull                          # убедиться что локальное состояние актуально
# отредактировать filters.toml
diff                          # проверить изменения перед отправкой
push
```

## Типичный рабочий процесс (продолжение)

**Исключить из папки все чаты другой папки:**
```
exclude 1 --from 2            # добавить peers фильтра 2 в exclude фильтра 1
diff                          # проверить изменения
push                          # применить
```

## Нереализованные возможности (вне скоупа)

- Операции над множествами через CLI помимо `exclude` (например, «добавить в Политику все каналы из Работы»). Пользователь делает это вручную в `filters.toml` или через внешние скрипты.
- Автоматический merge при конфликте pull. Конфликты разрешаются вручную.
- Импорт `exclude_from` зависимостей из Telegram — Telegram не хранит эту семантику, только плоский список peers.
